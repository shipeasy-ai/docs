One (deduped) **exposure** — the record the daily analysis uses to know who was in the test — is logged per enrolled unit. Usually the automatic timing is exactly right. But sometimes you resolve a variant well before the user sees it (a server prefetch, a component that may never mount), and you want "exposed" to mean "saw it".

<Callout type="info" title="There is no logExposure() call">
  Reading <em>is</em> the exposure — you never fire one by hand. What you control is whether a given
  read counts, and every SDK gives you a way to read without logging.
</Callout>

## When the exposure fires

**Server** — `assign()` is side-effect free; the exposure fires on the **first `get()` read** of an enrolled assignment. Pass `{ exposure: false }` to peek; the exposure then fires on the next real read.

```ts
const flags = new Client(user); // construct once per callsite

const cta = flags.universe("hero_cta").assign();

// Peek the params WITHOUT logging an exposure:
const preview = cta.get("primary_label", "Sign up", { exposure: false });

// …at the moment you actually render the treatment, read normally to log it:
render(cta.get("primary_label", "Sign up")); // logs the single exposure (deduped)
```

**Browser** — the visitor is already resolved, so the exposure fires at `assign()` time. Suppress it with `assign({ logExposure: false })` and re-`assign()` with logging on at render:

```ts
const flags = new Client(visitor); // construct once per callsite

const cta = flags.universe("hero_cta").assign({ logExposure: false });
render(cta.get("primary_label", "Sign up"));

flags.universe("hero_cta").assign(); // …log the exposure at render (deduped per session)
```

To make suppression the default for **every** read, set `disableAutoExposure: true` on `configure()` and opt back in per callsite with `assign({ logExposure: true })`.

Either way the exposure is deduped per session and durably per `(unit, experiment, group)` server-side.

## Other languages

Every SDK resolves a param the same way; only the peek spelling differs.

| SDK                                                  | Read without logging an exposure                                                            |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| [TypeScript](/sdks/reference/typescript/experiments) | `get(field, fallback, { exposure: false })` — browser also `assign({ logExposure: false })` |
| [Python](/sdks/reference/python/experiments)         | `a.get(field, fallback, exposure=False)`                                                    |
| [Ruby](/sdks/reference/ruby/experiments)             | `a.get(field, fallback, exposure: false)`                                                   |
| [PHP](/sdks/reference/php/experiments)               | `$a->get($field, $fb, false)`                                                               |
| [Go](/sdks/reference/go/experiments)                 | `a.Peek(field, fallback)`                                                                   |
| [Java](/sdks/reference/java/experiments)             | `a.peek(field, fb)`                                                                         |
| [Kotlin](/sdks/reference/kotlin/experiments)         | `a.peek(field, fallback)`                                                                   |
| [Swift](/sdks/reference/swift/experiments)           | `assign(logExposure: false)`                                                                |

## When to reach for it

- **Server prefetch** — you resolve the variant in a loader but the component may never render
- **Lazy UI** — a tab or modal that holds the variant but isn't always opened
- **Strict exposure semantics** — you want "exposed" to mean "saw it", not "was assigned"
