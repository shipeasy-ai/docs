## Shared

Project detection, binding, auth, the current project, and targeting attributes. Use these before any write tool — every write refuses to run until the cwd is bound to a project.

### `detect_project`

Inspect the working directory and return language, framework, package manager, shipeasy SDK install state (experimentation + i18n), and loader-script presence.

| Parameter |          | Type       | Description                                                              |
| --------- | -------- | ---------- | ------------------------------------------------------------------------ |
| `path`    | optional | `string`   | Single directory to analyze. Defaults to cwd.                            |
| `paths`   | optional | `string[]` | Multiple directories to analyze in one call. Takes precedence over path. |

### `projects_upsert`

Find-or-create a Shipeasy project by domain (idempotent) and bind the cwd to it via .shipeasy. Use this on fresh installs BEFORE any other write tool — every other write tool refuses to run until .shipeasy exists. Re-running with the same domain returns the existing project unchanged.

| Parameter |          | Type      | Description                                                                                    |
| --------- | -------- | --------- | ---------------------------------------------------------------------------------------------- |
| `domain`  | required | `string`  | Hostname-like identifier for the project (e.g. shouks.app, acme.com). Primary key for upsert.  |
| `name`    | optional | `string`  | Human-readable project name. Defaults to the domain on first create; ignored on later upserts. |
| `path`    | optional | `string`  | Directory to write .shipeasy in. Defaults to the MCP server's cwd.                             |
| `bind`    | optional | `boolean` | Write .shipeasy after upsert. Default true. Set false to skip binding.                         |

### `auth_check`

Report whether ~/.config/shipeasy/config.json holds a valid CLI token. Returns \{ authenticated, project_id, base_url, user_email \}.

_No parameters._

### `attributes_list`

### `release_flags_create`

Create a feature gate. A flat gate is `rules` + a single `rollout` %. For tiered rollouts (e.g. 'US @ 50% → bots @ 30% → everyone else @ 10%') pass `stack` — an ordered list of steps evaluated first-match-wins; flat `rules`/`rollout` are then ignored.

| Parameter |          | Type     | Description                                                                                                                                                                                                               |
| --------- | -------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`    | required | `string` | Gate key (lowercase, digits, \_/-).                                                                                                                                                                                       |
| `rollout` | optional | `number` | Rollout percentage, 0–100 (converted to basis points internally).                                                                                                                                                         |
| `rules`   | optional | `string` | Targeting rules as a JSON array, e.g. '[\{"attr":"plan","op":"eq","value":"pro"\}]'. AND-combined.                                                                                                                        |
| `salt`    | optional | `string` | Override hash salt (immutable after create).                                                                                                                                                                              |
| `stack`   | optional | `string` | Gatekeeper stack as a JSON array of ordered first-match-wins tiers (condition/rollout steps, rolloutPct in basis points). Takes precedence over flat rules/rollout. Pass to express internal ∪ beta ∪ public in one gate. |

### `release_flags_update`

Update a feature gate's rollout, rules, gatekeeper stack, or enabled flag. Pass `stack` to replace the tiered rollout wholesale; array fields replace, they do not merge.

| Parameter |          | Type      | Description                                                                                                                                                                                                                                                       |
| --------- | -------- | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`    | required | `string`  | Gate name to update.                                                                                                                                                                                                                                              |
| `rollout` | optional | `number`  | Rollout percentage, 0–100 (converted to basis points internally).                                                                                                                                                                                                 |
| `rules`   | optional | `string`  | Targeting rules as a JSON array, e.g. '[\{"attr":"plan","op":"eq","value":"pro"\}]'. AND-combined. Replaces the existing rules wholesale.                                                                                                                         |
| `stack`   | optional | `string`  | Gatekeeper stack as a JSON array of ordered first-match-wins tiers (condition/rollout steps, rolloutPct in basis points). Takes precedence over flat rules/rollout. Pass to express internal ∪ beta ∪ public in one gate. Pass null to revert to flat evaluation. |
| `enabled` | optional | `boolean` | Master switch — false forces the gate off for every caller.                                                                                                                                                                                                       |

## Ops

The unified operational queue (bugs, feature requests, error/alert tickets), alert rules, escalation notifications, and PR links. Registry-driven.

### `ops_list`

List the unified queue — bugs, feature requests, and auto-filed error/alert tickets. Filter by `type`, `status`, or `priority`.

| Parameter  |          | Type                                                                                          | Description             |
| ---------- | -------- | --------------------------------------------------------------------------------------------- | ----------------------- |
| `type`     | optional | `"bug" \| "feature_request" \| "error" \| "alert" \| "all"`                                   | Filter by type.         |
| `status`   | optional | `"open" \| "triaged" \| "in_progress" \| "ready_for_qa" \| "resolved" \| "wont_fix" \| "all"` | Filter by status.       |
| `priority` | optional | `"nice_to_have" \| "medium" \| "high" \| "critical"`                                          | Filter by priority.     |
| `limit`    | optional | `number`                                                                                      | Max rows (default 200). |

### `ops_get`

Show one queue item by number (#7 → 7) or id — any type.

| Parameter |          | Type     | Description        |
| --------- | -------- | -------- | ------------------ |
| `handle`  | required | `string` | Item number or id. |

### `ops_create`

File an operational item — a bug report or feature request — against the bound project. Fires the project's connectors (GitHub issue, Slack). error/alert tickets are auto-filed and cannot be created here.

| Parameter          |          | Type                                                 | Description                   |
| ------------------ | -------- | ---------------------------------------------------- | ----------------------------- |
| `type`             | required | `"bug" \| "feature_request"`                         | Item type.                    |
| `title`            | required | `string`                                             | One-line title.               |
| `body`             | optional | `string`                                             | Detailed description.         |
| `priority`         | optional | `"nice_to_have" \| "medium" \| "high" \| "critical"` | Priority.                     |
| `stepsToReproduce` | optional | `string`                                             | Repro steps (bugs).           |
| `pageUrl`          | optional | `string`                                             | Page URL the item relates to. |

### `ops_update`

Flip a queue item's status (any type) and optionally its priority.

| Parameter  |          | Type                                                                                 | Description        |
| ---------- | -------- | ------------------------------------------------------------------------------------ | ------------------ |
| `handle`   | required | `string`                                                                             | Item number or id. |
| `status`   | optional | `"open" \| "triaged" \| "in_progress" \| "ready_for_qa" \| "resolved" \| "wont_fix"` | New status.        |
| `priority` | optional | `"nice_to_have" \| "medium" \| "high" \| "critical"`                                 | New priority.      |

### `ops_link-pr`

Link the PR that fixed a queue item (any type). Records connector_data.github.pr. Pass `remove` to unlink.

| Parameter  |          | Type      | Description                                         |
| ---------- | -------- | --------- | --------------------------------------------------- |
| `handle`   | required | `string`  | Item number or id.                                  |
| `prNumber` | optional | `number`  | PR number.                                          |
| `url`      | optional | `string`  | Explicit PR URL (required for error/alert tickets). |
| `remove`   | optional | `boolean` | Unlink the PR instead of setting one.               |

### `ops_notify`

Raise an attention bell notification (agent escalation, create-only). Idempotent on the dedupe key — pass `item` to derive `feedback:<n>`, or an explicit `key`.

| Parameter |          | Type     | Description                                                      |
| --------- | -------- | -------- | ---------------------------------------------------------------- |
| `title`   | required | `string` | One-line headline of what's blocked.                             |
| `summary` | required | `string` | One sentence: why it can't be fixed in code.                     |
| `steps`   | optional | `string` | Steps the human should take, as a JSON array of strings.         |
| `href`    | optional | `string` | Dashboard-relative deep link.                                    |
| `item`    | optional | `string` | Queue item number this is about (sets dedupe key feedback:\<n>). |
| `key`     | optional | `string` | Explicit dedupe key (overrides item).                            |

### `ops_alerts_list`

List the project's metric-threshold alert rules the analysis cron evaluates.

_No parameters._

### `ops_alerts_channels`

List the project's Slack channels (for the `slackChannel` alert target).

_No parameters._

### `ops_alerts_create`

Create a metric-threshold alert rule. The metric (and its aggregation) is fixed for the rule's life — delete + recreate to repoint it. Optionally target a Slack channel/email.

| Parameter      |          | Type                             | Description                                             |
| -------------- | -------- | -------------------------------- | ------------------------------------------------------- |
| `name`         | required | `string`                         | Rule name.                                              |
| `metric`       | required | `string`                         | Metric to evaluate (id or name).                        |
| `comparator`   | required | `"gt" \| "gte" \| "lt" \| "lte"` | Comparison operator.                                    |
| `threshold`    | required | `number`                         | Threshold the metric value is compared against.         |
| `window`       | optional | `number`                         | Lookback window in whole hours (1–720). Defaults to 24. |
| `severity`     | optional | `"danger" \| "warn" \| "info"`   | Severity. Defaults to warn.                             |
| `disabled`     | optional | `boolean`                        | Create the rule disabled.                               |
| `slackChannel` | optional | `string`                         | Slack channel to post to (id or name).                  |
| `email`        | optional | `string`                         | Email address to notify.                                |

### `ops_alerts_update`

Update an alert rule's tunable knobs (by id, id-prefix, or unique name). The metric is immutable. Pass `clearTarget` to revert the rule's target to the project default.

| Parameter      |          | Type                             | Description                                   |
| -------------- | -------- | -------------------------------- | --------------------------------------------- |
| `rule`         | required | `string`                         | Rule id, id-prefix, or name.                  |
| `name`         | optional | `string`                         | New human label.                              |
| `comparator`   | optional | `"gt" \| "gte" \| "lt" \| "lte"` | Comparison operator.                          |
| `threshold`    | optional | `number`                         | New threshold.                                |
| `window`       | optional | `number`                         | New lookback window in whole hours (1–720).   |
| `severity`     | optional | `"danger" \| "warn" \| "info"`   | New severity.                                 |
| `enabled`      | optional | `boolean`                        | Enable/disable the rule.                      |
| `slackChannel` | optional | `string`                         | Set the Slack channel target (id or name).    |
| `email`        | optional | `string`                         | Set the email target.                         |
| `clearTarget`  | optional | `boolean`                        | Clear the target back to the project default. |

### `ops_alerts_archive`

Archive (delete) an alert rule by id, id-prefix, or unique name.

| Parameter |          | Type     | Description                  |
| --------- | -------- | -------- | ---------------------------- |
| `rule`    | required | `string` | Rule id, id-prefix, or name. |

## SDK docs

Fetch SDK documentation — feature pages, nested snippets, and installable skills — from each SDK's published GitHub Pages docs.

### `docs_list`

Fetch an SDK's `/docs/manifest.json` and return the doc tree — the feature-reference pages, the nested snippet groups, and whether an installable skill exists. The runtime 'explore' step before fetching a specific page or snippet.

| Parameter |          | Type                                                                                                                     | Description   |
| --------- | -------- | ------------------------------------------------------------------------------------------------------------------------ | ------------- |
| `sdk`     | required | `"typescript" \| "javascript" \| "node" \| "ts" \| "python" \| "go" \| "java" \| "kotlin" \| "php" \| "swift" \| "ruby"` | SDK language. |

### `docs_get`

Fetch one feature-reference page (`flags`, `experiments`, …) or nested snippet (`release/experiments`, `i18n/setup`, …) from the SDK's published docs, substituting declared \{\{placeholders\}\} from caller args. Replaces the old `get_sdk_snippet`.

| Parameter   |          | Type                                                                                                                     | Description                                        |
| ----------- | -------- | ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------- |
| `sdk`       | required | `"typescript" \| "javascript" \| "node" \| "ts" \| "python" \| "go" \| "java" \| "kotlin" \| "php" \| "swift" \| "ruby"` | SDK language.                                      |
| `path`      | required | `string`                                                                                                                 | Page key or snippet 'group/resource'.              |
| `framework` | optional | `string`                                                                                                                 | Framework hint (substitutes \{\{FRAMEWORK\}\}).    |
| `name`      | optional | `string`                                                                                                                 | Resource name (substitutes \{\{RESOURCE_NAME\}\}). |

### `docs_skill`

Fetch the SDK's `skill/SKILL.md` (YAML frontmatter intact) so an agent can install it verbatim into its skills directory. The CLI's `--install` writes it locally (a consumer fs side-effect layered on the fetch); the op itself just returns the bytes.

| Parameter |          | Type                                                                                                                     | Description                                              |
| --------- | -------- | ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| `sdk`     | required | `"typescript" \| "javascript" \| "node" \| "ts" \| "python" \| "go" \| "java" \| "kotlin" \| "php" \| "swift" \| "ruby"` | SDK language.                                            |
| `install` | optional | `boolean`                                                                                                                | CLI only: write the skill to the local agent skills dir. |
