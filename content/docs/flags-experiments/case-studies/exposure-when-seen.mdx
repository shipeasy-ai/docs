Your experiment lives in a tab that most users never open. But your server loader resolves the variant for everyone up front to render the page — so every user gets an **exposure**, including the ones who never see the tab. Your "exposed" population is now mostly people who weren't exposed to anything, and the effect you're measuring is diluted toward zero.

The fix is [exposure control](/sdks/manual-exposure): read the variant without counting it, then let the read at render time count it.

**The shape:** decouple _resolving_ from _counting_. On the server, `assign()` logs nothing at all — the exposure fires on the first `get()` read. So the only thing you need is to make the early read a **peek**.

## 1. Peek in the loader

`assign()` is side-effect free, so prefetching an assignment costs you nothing. Pass `{ exposure: false }` on any read you do before the user can see the variant:

```ts
import { configure, Client } from "@shipeasy/sdk/server";

configure({ apiKey: process.env.SHIPEASY_SERVER_KEY! });

const flags = new Client({ user_id: "u_4f2a" });

// no exposure — assigning is free
const cta = flags.universe("checkout").assign();

// peek: resolve the value for the payload without counting the user as exposed
const color = cta.get("color", "blue", { exposure: false });
```

## 2. Let the render count it

From the code path that actually mounts the variant, read normally. That first real read logs the single (deduped) exposure:

```ts
// in the component / handler that actually shows the variant
render(cta.get("color", "blue")); // logs the exposure, once
```

In the **browser** the visitor is already resolved, so the beacon fires at `assign()` time instead. Suppress it there and re-assign at render:

```ts
const cta = flags.universe("checkout").assign({ logExposure: false });
render(cta.get("color", "blue"));

flags.universe("checkout").assign(); // …count it at render (deduped per session)
```

To make suppression the default everywhere, set `disableAutoExposure: true` on `configure()` and opt back in per callsite with `assign({ logExposure: true })`.

<Callout type="warn" title="There is no logExposure() call">
  You never fire an exposure by hand — reading <em>is</em> the exposure. The clean contract is: peek
  wherever you resolve early, and read normally exactly where the user sees the variant. Duplicates
  are deduped by the pipeline anyway.
</Callout>

## Rollout & measurement plan

- **"Exposed" should mean "saw it."** With the peek/read split your denominator is the people who actually reached the surface, so the measured lift is the real one
- **Audit the render path.** The bug to avoid is a plain `get()` in a code path that runs even when the component doesn't mount — keep the counting read as close to the render as you can
- **Prefetch + lazy UI are the classic cases.** Server loaders, tabs, modals, and routes that may never open are exactly where auto-exposure over-counts
