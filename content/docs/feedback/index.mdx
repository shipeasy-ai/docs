## Two record types

<TileGrid>
  <Tile href="#bugs" icon="◎" title="Bugs — what's broken">
    Title, page URL, optional stack trace and screenshot. Status flow: `open` → `in progress` →
    `ready for QA` → `resolved`, with `won't fix` and `dismissed` as terminal exits.
  </Tile>
  <Tile href="#feature-requests" icon="✦" title="Feature requests — what's missing">
    Title, importance (`nice-to-have` / `important` / `critical`), votes from other users. Status
    flow: `open` → `planned` → `shipped`.
  </Tile>
</TileGrid>

## How it works [#how-it-works]

A user hits **Report bug** in your app. The SDK sends the report to Shipeasy. You see it in the
dashboard within seconds. Optional [connectors](/feedback/connectors) forward it to GitHub,
Google Sheets or Slack so you don't have to live in a second tool.

## Hand a ticket to a coding agent

Any ticket in the queue can be handed to a coding agent: mention the agent in
a comment — `@claude`, `@cursor`, `@copilot` or `@jules` — and that agent
starts work on the item and reports back on the ticket. Four agents can be
mentioned today: Claude Code, Cursor, GitHub Copilot and Gemini (Jules); each
one first has to be connected for the project under **Settings → Triggers**.

Project owners control this under **Settings → Ops → Agent mentions** — the
switch is on by default, and it also decides which of the connected agents
get one-tap mention chips on a ticket.
