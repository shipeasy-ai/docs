## Two record types

<TileGrid>
  <Tile href="#bugs" icon="◎" title="Bugs — what's broken">
    Title, page URL, optional stack trace and screenshot. Status flow: `open` → `in_progress` →
    `ready_for_qa` → `resolved`, with `wont_fix` as the exit for anything you decide not to change.
  </Tile>
  <Tile href="#feature-requests" icon="✦" title="Feature requests — what's missing">
    Title, description and use case. Same status flow as bugs, so one queue and one set of filters
    covers both.
  </Tile>
</TileGrid>

## How it works [#how-it-works]

A user files a report from your app with the [devtools overlay](/feedback/devtools). You see it on
**Home**, the project's ops queue, within seconds, alongside tracked errors and fired alerts. A
[connector](/feedback/connectors) can mirror it to GitHub, Google Sheets or Slack so you don't have
to live in a second tool.

## Hand a ticket to a coding agent

Any ticket in the queue can be handed to a coding agent: mention it in a comment (`@claude`,
`@cursor`, `@copilot` or `@jules`) and it starts work on the item and reports back on the ticket.
Each agent first has to be connected under **Settings → Triggers**, and mentions are **off by
default** — a project owner switches them on under **Settings → Ops**. See
[Mention an agent in a comment](/get-started/triggers#mentions).
